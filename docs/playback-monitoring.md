# 播放健康定时监控

2026-11-27 起，仓库用定时探针持续检查播放链路，故障时自动开 issue，恢复后自动关闭。
目标是**把「用户碰到才发现」变成「几十分钟内自动发现并带上定位证据」**。

## 不能做什么

这类故障**不会被自动修复**。2026-11-27 的事故是官网 player 页改版（`vid_list` 只下发 3 个
`v1_` 不透明标识）叠加备用接口开始要求 V5 签名；两者都需要对照真实报文重新定位协议，
重试或改常量都无法恢复。因此本项目只做「自动发现 + 自动定位 + 自动建单」：

- 不远程下发签名配置（`src/native/playback-profiles.js` 明确禁止，避免新增信任面）。
- 不猜签名常量、不伪造取源成功（`AGENTS.md` 的既有约束）。
- 不自动发版。发行不可变、标签名不可复用（6.39 的教训），自动发布一旦出错无法回退版本号。

## 三层结构与采样

`.github/workflows/playback-probe.yml` 调用 `scripts/probe-playback-health.cjs`，依次验证：

| 层 | 验证内容 | 失败含义 |
| --- | --- | --- |
| `catalog` | 官网类别页能否列出候选剧 | 官网目录入口整体不可用 |
| `episodes` | 每部剧能否取到集数>0、序号唯一且从 1 连续的分集 | 分集目录层改版或被拦截 |
| `source` | 首/中/末分集能否取到播放地址，并记录 `web`/`app` 线路矩阵 | 取源通道不可用 |
| `media` | 对取到的地址按 `Range: bytes=0-1023` 读前 1KB | 地址拿到了但 CDN 不能取流 |

`source` 层的线路矩阵是关键证据：2026-11-27 之后官网线路只提供预览（探针实测 `web` 全部
`HTTP_404`），实际取源全靠 `app` 通道。`app` 一旦也失败就没有退路，矩阵能把这种状态直接显示出来。

采样（`--scope`）：

- `light`：2 部随机剧 × 首/中/末 3 集，含媒体探测。
- `full`：3 部随机剧 × 首/25%/50%/75%/末 5 集，含媒体探测。

触发频率：`light` 每 30 分钟（每小时 7 分与 37 分），`full` 每 6 小时（17 分）；
都避开整点，因为 GitHub 的调度高峰在 `:00` 附近，容易延迟甚至被丢弃。
另支持手动 `workflow_dispatch` 并选择深度。

## 误报控制

监控一旦误报，就没人再看它。四道闸：

1. **单次重试**：每部剧目录请求最多两次，第二次绕缓存；重试成功记为 `recovered`，不算故障。
2. **单剧失败不升级**：一部剧目录失败可能只是该剧下架，只有全部失败才判 `episodes` 层故障。
3. **采样失败率阈值**：`source`/`media` 层只有失败率 ≥ 50% 才升级为硬故障，个别分集失败记 `degraded`。
4. **告警去重与限流**：故障指纹只由「层 + 错误码」生成、不含剧号，同类故障合并到同一 issue；
   同一 issue 每天最多追加一条评论。

## 告警流程

由 workflow 内的 `actions/github-script` 维护，权限只有 `contents: read` 与 `issues: write`：

- 故障且无同指纹 issue → 新建，标题含指纹标记 `[playback-health:<指纹>]` 与失败层/错误码，
  正文含分层状态表、线路矩阵和运行链接。
- 故障且已有同指纹 issue → 当天未评论过时追加一条「故障仍在持续」。
- 探针自身崩溃（报告缺失/不可解析）→ 按 `probe/PROBE_CRASHED` 报警，不静默。
- 恢复健康 → 评论「探针已恢复正常」并自动关闭全部探针 issue。

报告与 issue 正文都不含媒体地址、设备标识、签名串或账号信息；分集编号只在内存中用于取源。

## 本地使用

```bash
node scripts/probe-playback-health.cjs --scope light                       # 打印报告，退出码表示健康
node scripts/probe-playback-health.cjs --scope full --output health.json  # 同时写报告文件
node scripts/probe-playback-health.cjs --series 7706404415887903806      # 只检查指定剧
node scripts/diagnose-playback.cjs 7706404415887903806                    # 单剧快速诊断（历史脚本）
```

退出码：健康 `0`，有硬故障 `1`。

## 检查

| 检查 | 覆盖内容 |
| --- | --- |
| `scripts/check-playback-probe.cjs` | 分层判定、重试恢复、单剧不升级、阈值边界、指纹去重、报告不泄漏分集编号与媒体地址 |
| `scripts/check-playback-alerting.cjs` | 从 workflow 抽取告警脚本，用假 github 跑：开单、去重、同日限流、恢复关闭、崩溃报警 |
| `scripts/check-workflow-governance.cjs` | 探针权限必须恰好是 `contents: read` + `issues: write`，action 必须钉 SHA |

告警脚本的检查是刻意保留的：它只在故障时执行，健康运行时永远不会暴露它的 bug。

## 已知边界

- 探针采样的是随机剧的少量分集，**不等于全量**。某一集偶然不可播不会告警，也不应据此推断整部剧。
- CI runner 的网络与地区同真实用户不同，探针通过不代表所有用户线路都可播。
- 只覆盖公开可访问的链路；账号、付费与 DRM 授权状态不在探针范围内。
- 探针是只读的：只取地址与媒体头部字节，不下载整集、不写任何本地资料。
