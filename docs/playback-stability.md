# 播放稳定性改造与验收记录

记录日期：2026-11-25。本文对应播放稳定性开发候选，当前源码目标为 `6.34.0`；最终本地全量测试、渲染构建、Windows x64 NSIS 构建及完整依赖审计通过。已有真实账号恢复，以及最终打包应用的本地交互、官网在线连播和损坏副本恢复回执；冻结标签 CI、真实安装卸载、旧版升级及发布仍未完成。本文不代表已正式发布。开发候选汇总见 [6.34 发行记录](release-6.34.md)。

## 已确认的问题与未确认的原因

- 账号扫码登录与 App 播放原先使用独立身份。网页账号验证成功，不能证明网页 Cookie 能用于 App 播放，也不能证明具备某个分集的播放权限。
- 请求画像、签名关联字段和线路参数散落在多个模块，接口变化时容易出现只修改一部分参数的情况；空响应、媒体加载失败与解码失败也需要按实际发生层级处理。
- [6.28 历史实测](release-6.28.md)曾确认：`7.4.5.32` 画像、`preload/v1`、`dr_scene=preload`、`device_level=2` 与 Medusa 字段 21=`312` 必须配套。该历史结论不能作为今天接口可用的证明。
- 早期匿名实测使用两个独立播放身份，各请求三条已有官方线路，共六次请求，全部为 HTTP 200、正文为空。后续使用用户扫码取得的有效账号，在同一设备、同一请求画像和同一签名请求上比较匿名与账号 Cookie，仍均为 HTTP 200 空正文。当前没有证据把原因确定为签名错误、设备过期或缺少账号授权；没有猜改协议常量。
- 网页受保护播放与官网公开播放是不同路径。配对实测中，网页播放器页与 `play-info` 的匿名/账号响应均指向受保护播放器，未证明 Cookie 增加播放权限；后续从官网公开线路取得并完整静音解码了两个连续完整分集，不据此宣布 App 接口恢复。
- 缓存到期与媒体地址到期是不同事件。当前使用显式到期字段和媒体阶段的实际失败来决定重新取源，不从不透明签名猜测有效期。
- 取消解密原先会先结束外层等待，使仍在进行的本地清理脱离退出与安装保护；现在实际清理任务独立登记，取消返回后仍等待受控资源释放。立即取消 A 并开始同集 B 的缓存竞态也已修复，不再继承 A 的取消结果或额外等待 500 毫秒。
- Chromium 拖动播放进度时会取消旧的媒体读取。原实现把这种取消记作 `ECONNRESET` 或流提前关闭，触发不必要的重新连接；现在先标记消费者取消，再中止上游，不把正常拖动记录为媒体故障。
- 可恢复的中间候选失败原先可能提前上报为播放故障；现在由受控候选链路确定最终结果。取消后不再让该轮迟到诊断改变当前状态，明确鉴权拒绝或限流仍立即停止。
- 原元数据回调跳过距片尾不足 3 秒的恢复位置，导致在线测试难以从片尾继续并产生真实 `ended`；现保留该进度并限制在 `duration - 0.1` 以内，不以脚本伪造结束事件。
- 首帧后的正常播放仍沿用初始 90 秒准备期限，长时间暂停后可能无法恢复；现正常首帧结束未使用的初始期限，实际故障恢复仍共享有界预算。离开播放器或关闭画中画时也会关闭扫码提示并阻止晚到登录结果重新取源。

**账号 CK 的实测结论：本轮没有证明网页账号 Cookie 可以恢复 App 播放鉴权。** 真实扫码、加密保存、重启后重新验证和 50 条账号观看记录均已通过；App 同签名配对请求携带 Cookie 后仍无播放模型。默认 App 取源不盲目传递 Cookie，也不将本地账号/设备关联显示为平台已经完成授权。

Electron `45.5.0` 的本机合成传输测试已确认：`credentials: 'omit'` 会排除环境 Cookie jar，但允许显式 `Cookie` 请求头。该结果只证明传输行为，不证明红果服务端接受这种鉴权。证据为 `dist/account-transport.json`，测试不使用真实账号。

## 账号与播放架构

保留现有扫码登录和播放器，统一入口为 `hongguo.fetchPlayUrlSingle → PlaybackManager.resolve`；在线播放、下载等既有调用通过该入口取源。采集源、搜索、剧库、NAS 和更新流程继续复用原有模块。

| 责任 | 主要模块 | 处理内容 |
| --- | --- | --- |
| 账号会话 | `account-session.js`、`account-web-login.js` | 加密保存、启动恢复、有效性验证、Cookie 轮换、并发刷新、登出取消 |
| 播放调度 | `playback-manager.js` | 播放前检查账号、共享取源、总预算、取消传播、账号代际失效 |
| 播放设备 | `playback-device.js` | 独立匿名播放身份、并发初始化、依据明确失效证据更新、冷却控制 |
| 请求配置 | `playback-profiles.js` | 端点、画像、UA、请求头、签名关联字段、超时及兼容记录 |
| 签名与取源 | `playback-signature.js`、`playback-v5.js`、`app-source.js` | 按最终请求签名、验证分集模型、有限线路阶梯、实际请求统计 |
| 官网公开取源 | `official-web-playback.js` | 只接受官方明确公开的分集，校验身份、权限范围、有效期、媒体格式和完整时长 |
| 媒体访问 | `media-url-manager.js`、既有媒体/HLS 模块 | 到期判断、URL 与请求头/密钥绑定、媒体会话与加载故障 |
| 故障与诊断 | `playback-errors.js`、`playback-diagnostics.js` | 统一分类、固定字段脱敏、取源/媒体/首帧成功分开统计 |
| 播放控制 | `Player.jsx`、`playbackRecovery.mjs`、主进程 IPC | 进度保留、兼容解码、离线恢复、总恢复预算、晚到结果释放 |

四类身份分别管理：账号会话随登录、验证、过期和登出变化；播放设备只在初始化或明确失效时更新；请求会话随单次取源、取消和截止时间结束；媒体会话随 URL、绑定请求头、密钥和账号代际变化。账号与播放设备目前只有本地关联，`platformVerified=false`，不得展示为平台已经完成账号设备绑定。

账号验证有 60 秒有效性缓存，并发刷新共享一次真实验证。取消一个调用不影响其他调用，最后一个调用取消时终止传输。账号过期、无效和网络暂不可用分别表示；临时网络失败保留加密凭据但不伪装成验证成功。退出登录清除会话并阻止晚到请求恢复旧账号。无法使用安全加密后端时不降级明文保存。

## 请求配置与有限恢复

当前配置记录为 `hongguo-app-74532-medusa312-v1`，版本 `2026-11-24.1`。设备注册画像与播放请求画像有各自记录，不强行统一为同一版本。配置管理只接受内置、结构兼容的记录，未知配置或不兼容响应可回退到最后验证过的兼容记录；目前没有已验证的远程官方配置源，也没有动态下载签名或账号凭据。

三条既有线路保留历史证据与当次结果，当前均未恢复成功。`historically-verified` 表示历史验证，只有当次匹配分集模型成功后才记录 `verified-this-process`；模型成功仍不等于媒体加载或实际播放成功。

新增官网公开配置为 `hongguo-official-web-public-v1`、版本 `2026-11-25.1`，线路 `official-web-public-fallback`。端点和请求形状来自官方播放器脚本，只有官方页面明确标记无需登录、无账号播放和浏览器加密要求、免费且处于可访问分集范围时才进入。公开接口地址还须符合官方 CDN 白名单、有效期及无预览标记，MP4 不得包含加密样本条目，实际媒体时长必须与官方完整分集元数据一致。第 1 集的参照时长来自官方 SEO；后续分集缺少该元数据时仅读取官方 `play-info` 中的完整时长，不取用其受保护地址或密钥。

旧 `hongguo.js` 中绕过统一配置的独立 App 播放回退已停用；搜索与分集目录的原有 API 保留。连接诊断的目录请求使用独立取消生命周期，取消诊断不影响普通页面共享请求。HLS 明确拒绝不会继续换候选；已知地址过期时可以重新取源，HTTP 429 始终停止。

- 原生统一取源总预算默认 30 秒，包含账号检查；最多两次外层尝试，仅用于允许恢复的临时网络故障或已过期媒体地址，不重复执行已耗尽的接口空响应阶梯。
- App 配置总预算 28 秒，模型预算 20 秒，单请求上限 12 秒，设备注册上限 8 秒；各步骤受剩余预算约束。临时网络重试最多一次，明确设备失效最多更新一次；空正文不会触发无依据的设备轮换。
- HTTP 401/403/429、明确业务拒绝与取消停止该取源链路；空正文最多走一次既有三路线阶梯，不把拒绝当网络错误重试。
- 播放准备或实际故障恢复窗口总计 90 秒、最多六项恢复动作；连续质量切换不重置实际恢复的总截止时间。正常首帧结束尚未触发恢复的初始准备期限，正常暂停不会耗尽下一次故障恢复预算。离线时等待网络事件，取消或预算到期后不在网络恢复时自行重启。
- 显式媒体到期前保留 5 秒安全余量。重新取源携带原清晰度和强制刷新标记，尽可能恢复进度、暂停意图、倍速、音量和静音状态。切集及自动连播仍走统一入口，不能无限复用过期地址。
- 有明确的解码错误或编码兼容性证据才进入兼容解码。取源失败、CDN/HLS 失败和解密失败保持各自阶段；首帧提交后才记录播放成功，取得 URL 或加载元数据不会提前记成功。

| 故障类型 | 处理策略 |
| --- | --- |
| `ACCOUNT_EXPIRED` | 停止账号请求，提示重新扫码 |
| `ACCOUNT_UNAUTHORIZED` | 停止恢复，提示在官方客户端确认内容授权 |
| `DEVICE_IDENTITY_EXPIRED` | 原生层仅凭明确证据有限更新身份，失败后停止 |
| `SIGNATURE_INVALID` | 原生层按最终请求重新签名；明确拒绝向上报告后播放器停止，不猜改常量 |
| `API_EMPTY_RESPONSE` | 记录 HTTP/结构证据，执行一次已有官方阶梯，耗尽后停止 |
| `API_RATE_LIMITED` | 停止自动重试，账号验证保留限流冷却 |
| `API_FORBIDDEN` | 停止自动重试，不以降画质或换设备绕过 |
| `NETWORK_TIMEOUT` | 在次数和总预算内重试，耗尽后提示 |
| `NETWORK_DISCONNECTED` | 有界等待网络恢复，保留播放意图，支持取消 |
| `MEDIA_URL_EXPIRED` | 同画质重新取源一次并恢复进度 |
| `CDN_UNAVAILABLE` | 区分媒体访问失败，有限刷新片源，不直接判定解码失败 |
| `MEDIA_DECRYPT_FAILED` | 独立标记解密阶段，当前自动链路停止，由用户重试重新取源；不当成解码故障 |
| `CODEC_UNSUPPORTED` | 使用既有 H.264 兼容策略；手动固定画质不擅自降级 |
| `PLAYER_DECODE_FAILED` | 使用既有兼容转码及有界恢复，保留进度 |

策略表描述可允许的恢复动作，不意味着每层都再执行一轮；具体执行受原生与播放器总预算约束。未知故障默认停止，用户取消不计为播放错误。

## 安全与播放诊断

账号凭据继续使用 Electron `safeStorage` 的系统加密后端；兼容已有加密会话，不迁移为明文 CK。Cookie 按有效域、路径、安全属性和到期信息筛选；账号播放探测限制为精确官方主机及路径，并禁止跳转。普通取源配置、渲染层和诊断不携带账号 CK，不通过凭据绕过内容权限。

官网登录弹窗使用无 `persist:` 前缀的独立内存分区 `hongguo-account-login`，不把新登录 Cookie 留在默认持久 Cookie 库。启动迁移、账号过期及退出会清理历史默认库中的红果官方 Cookie；清理失败明确报错，仍继续尝试其余清理，不输出原始凭据异常。退出账号同时失效播放关联和待恢复进度。

包入口改为最小 `app-entry.cjs`：正常启动载入原 `main.js`，仅 `--uninstall-account-data` 进入独立账号清理助手。NSIS 真正卸载前清理两种已知历史资料目录的官方 Cookie 和加密会话文件；更新/覆盖安装的 `--updated` 路径跳过账号清理，保留资料。清理助手不载入主界面或普通资料存储，拒绝并发应用及任意 `--user-data-dir`，不删除设置、下载视频或无关域 Cookie；清理失败会阻止卸载继续，已覆盖的失败场景保留撤销标记以防旧会话恢复。该实现已有专项证据，最终候选安装器仍须独立验收。

设置页增加独立「播放诊断」区域，展示 14 项状态，并提供检查账号、测试播放连接、导出报告三个操作。报告只接受固定状态、故障枚举、数值和内置配置/线路标识，不导出原始异常、完整 Cookie、账号 ID、设备标识、密钥、签名或完整媒体 URL。线路模型成功率、真实媒体加载与首帧播放成功分别记录。

未登录或账号失效且符合取源故障条件时，播放器可自动打开原有扫码登录组件；用户确认后仅在仍停留于同一播放选择时重新取源，扫码状态不替代平台内容授权。窗口明确说明账号资料与凭据只在本机保存、使用系统加密并仅用于红果官方服务，退出或真正卸载时清除本机账号数据。覆盖升级不走卸载清理路径；清理失败阻止真正卸载继续，避免把失败显示为已经清理。

NAS NFO 归属检查改为 XML 解析，拒绝畸形文档及注释、描述、CDATA 等位置的伪身份，保留已有文件与独占写入保护。远端安全告警的历史处置理由仍待重新核对与修正，本地专项通过不代表远端所有安全事项已处理完毕。
