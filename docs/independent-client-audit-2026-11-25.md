## 4. 点击播放到首帧的完整调用链

1. 发现详情或搜索详情的播放按钮调用 `electronAPI.playSeries`；选中分集会确定真实
   `seriesId`、`vid` 和 `vidIndex`，不从推荐条目拼接当前播放身份。
2. `preload.js` 通过固定通道发送 IPC；`main.js` 的统一处理器先检查可信主窗口与主 frame。
3. `play-series` 只接受已登记剧集，发送实际导航消息；`Player.jsx` 读取
   `getSeriesEpisodes`，决定复用已授权完整本地文件还是准备在线播放。
4. 前端 `prepareOnlinePlay` 携带请求标识、清晰度、取消和恢复意图；主进程建立随机
   `streamId`，在退出/安装保护下登记准备和清理任务。
5. `hongguo.fetchPlayUrlSingle → PlaybackManager.resolve` 执行账号上下文检查、
   共享取源、到期判断、总预算和取消。账号上下文不会自动把 Cookie 广播到所有来源。
6. 来源调度按当前质量策略处理官网公开线路或 App 兼容线路。播放器的自动质量会优先
   申请 1080P 并允许有界降级；不能据界面“自动”推断一定先走官网。手动固定质量不擅自降级。
7. 解析器检查 HTTP、正文、业务码、剧集/分集身份、访问许可、URL、有效期和模型。
   官网公开路径另检查官方 CDN、MP4 格式、非加密样本与完整参考时长；取得字符串不算成功播放。
8. 主进程只把随机 `hongguo-stream` 媒体能力地址返回前端，不将 CDN 签名 URL 或本地文件路径当普通业务数据展示。
9. Chromium 请求媒体时，主进程按 Range 和绑定请求头读取上游。HLS 走受控暂存及重封装，
   已有其他媒体兼容处理独立；网络错误页面、部分错误响应和已过期媒体不能当视频。
10. `Player.jsx` 的原生 `<video>` 加载媒体；有编码兼容证据时使用现有 H.264 兼容转码，
    不把取源失败误归为解码失败。加载、缓冲、网络、解码和取消有各自状态。
11. `loadeddata` 与实际 `requestVideoFrameCallback` 分别推进解码/首帧证据。
    首帧提交后才记录播放成功，并保留切集前的上一帧；元数据或媒体字节不替代首帧。
12. 进度保存、暂停意图、音量/静音和倍速随既有逻辑维护；真实 `ended` 驱动下一集。
    换集、seek、离开页面与取消必须释放上轮会话，迟到结果不得重新启动旧分集。

## 5. 原始问题与根因结论

### 已有历史问题与当前未知原因

6.28 历史记录确认过 App 请求画像和 Medusa 字段配套的兼容差异，但那是当时的实测，
不能作为 2026-11-25 的接口健康证明。6.34/6.35 记录明确保留 App HTTP 200 空正文问题。
当前没有证据把空正文确定为签名、账号、设备失效或缺少 Android 手机；本轮不猜改常量、
不增加伪造设备证明，也不把轮换身份当作授权替代。

旧 6.29 工作目录缺少主线后续的官网公开许可路径、统一播放会话及稳定性改造，
是本次必须先整合主线的直接原因。主线已有独立播放器，无需引入手机投屏或播放服务器。

### 本轮审计确认并实施的局部修复

| 问题 | 原因 | 修改位置与处理 |
| --- | --- | --- |
| 搜索错误被当作无结果/继续请求 | 原解析只检查字符串业务码，且限流/拒绝进入统一重试或其他检索线路 | `hongguo-search.js`、`main.js` 搜索分派：明确 401/403/429 停止重试与跨线路；其他数字业务码不再伪装为空成功，错误不写入成功缓存。 |
| App 搜索指向错误剧号 | JSON 大整数可能先被 Number 舍入，再被字符串化 | `hongguo-app-search.js`：解析前保留 `series_id` 大整数，拒绝已舍入的不安全 Number。 |
| App 备用详情分集号失真 | 原始数值 `7704506232622550078` 经普通 JSON 解析变为 `7704506232622550000`，后续 String 不能恢复 | `hongguo.js` 复用既有 `preserveLargeJsonIntegers`，只保留 `vid`/`series_id` 字段；映射前拒绝已失精度 Number。内存桩覆盖实际 `fetchEpisodeList`，不把该解析缺陷混同于后段原始空正文。 |
| 详情永久加载 | 详情/切季 IPC 缺少前端分段等待上限，永久挂起时 finally 不执行 | `Browse.jsx`、`SearchPanel.jsx`、`HongguoDownload.jsx`：每段 `waitForRequest` 默认最多等待 25 秒；Browse 详情与本机状态两段串行，最坏合计约 50 秒。请求代际与离页检查阻止迟到结果覆盖界面；停止 renderer 等待不等于取消已发出的 IPC。 |
| 明细缺少真实简介 | 目录解析丢弃 `series_intro`，详情界面也没有展示 | `hongguo.js` 及两个详情组件：保留来源实际字段，以普通 React 文本展示；不合成演员资料。 |
| 收藏写失败仍显示成功 | `saveLocalSeries` 返回 `{error}` 而非抛错，调用方无条件更新并 toast | `Browse.jsx`：检查失败返回值，保留原收藏状态并显示真实错误。 |
| 收到媒体头后停止传输时底层读取挂起 | 普通 Axios stream 的请求超时不能替代 Response 返回后的正文读取期限 | `media-response-body.js` 与主进程直通流：仅在有需求的 pending read 期间计空闲，超时销毁上游；暂停背压不算网络停滞。 |
| 取消后仍有未结束读取 | 只 abort 上游而不终结等待中的 Web reader | 同一响应体封装：取消/abort/结束清理计时器与监听，并结束消费者等待。 |
| 下载错误可能泄露请求资料 | 原始 Axios error 含 config/headers/带签名地址，可能被完整日志或 error.message 保存 | `download-error.js` 与下载失败处理：只构建允许的分类码、HTTP 状态和固定说明，不输出原始异常。 |
| 官网后段不可用误导账号提示与重复预取 | 未把当前官网入口未提供目标分集，与明确账号拒绝分别归类；后台预取可能继续尝试确定不可用的分集 | 工作区新增 `WEB_EPISODE_UNAVAILABLE` 非账号故障、终止恢复策略及预取失败上限，修正文案和扫码入口；HTTP 证据与未完成验收见第 10 节。 |

这些问题不需要重写签名、设备注册、播放器或整体 UI。受保护内容缺少正式授权能力的情况，
也不能通过“重写一个 Provider”解决。

## 6. 安全、会话与格式边界

账号 Cookie 使用现有系统安全存储；无法使用可信加密后端时不降级明文持久化。
Cookie 按官方域、路径、安全属性和到期筛选，登出/失效会失效相关任务。
播放设备、账号会话、单次请求和媒体会话分别管理；本地关联不等于平台完成设备授权。
固定协议配置属于历史兼容实现，不是从本轮手机抓取后写死的临时账号令牌。

现有 IPC、导航与媒体 URL 防护继续保留，包括可信调用方、任意外链限制、公网地址校验、
本地文件后缀/归属和随机能力地址。新日志/报告不应包含真实账号、Cookie、Token、
设备 ID、内容密钥或带签名媒体 URL；依赖审计及远端安全快照须以最终检查时间为准。

| 格式/能力 | 代码与验收边界 |
| --- | --- |
| 明文 MP4、H.264/AAC | 原生 video 与主进程 Range 路径；第 9 节保存后段修复前的两集完整文件静音解码与 6.37.0 打包应用播放基线，不代表新修复或后段集数通过。 |
| HEVC/H.265 | 有既有编码选择及 H.264 兼容转码；不承诺所有 Windows GPU、驱动和系统 codec 环境均原生可播。 |
| HLS/M3U8、TS/fMP4 | `hls-media.js` 对结束的 VOD 清单、分片和相关资源进行受控暂存，再 FFmpeg 重封装；不宣称完整直播或所有 HLS 规范支持。 |
| HLS 加密标记 | 现有代码仅认识特定既有方式，不能由“技术可处理”推导内容授权；本轮不扩展密钥获取或 DRM 绕过。 |
| DASH | 当前未集成通用 DASH 播放链，不列为本轮已支持或已验收。 |
| DRM/付费/设备证明 | 没有可用官方 EME/CDM/许可证服务集成证据，明确不算通过；保留官方客户端观看入口或正式授权方案。 |

本轮实际媒体为 MP4，继续使用 Chromium 原生 video 加既有 FFmpeg 路径。
仅增加 hls.js、Shaka 或 mpv 不能使空响应变成有权播放的资源，因此不盲目并装多个播放器。
若后续有正式授权的 DASH/DRM 服务，应以其官方许可协议、CDM 和许可证服务器单独评估。

参考原始文档：

- [Electron 安全清单](https://www.electronjs.org/docs/latest/tutorial/security)：sandbox、contextIsolation、IPC 调用方与远程权限。
- [hls.js 官方实现](https://github.com/video-dev/hls.js)：MSE HLS 播放方案；不提供平台内容授权。
